- Approach:
  - Query parameter `month: YYYY-MM` validated against `^\d{4}-(0[1-9]|1[0-2])$` and range `1990 <= year <= 2100`.
  - If omitted, default to the current month in the user's timezone (`user_meta.timezone`).
  - Calculate boundaries: 1st of month through last day (`calendar.monthrange(year, month)[1]`).
  - Fetch existing daily logs within month date range in single query via `repo.get_daily_logs_range`.
  - Decrypt payloads to populate `flow` and set `has_log = True`.
  - For unlogged days, `has_log = False` and `flow = None`.
  - Placeholders: `predicted = False`, `fertile = False`, `events = []`, `doses = []`.
  - Require valid authenticated session; user data isolated by tenant transaction.
- Migrations: None.
- New dependencies: None.

## Decisions

- **CalendarDay fields**: Includes `date`, `flow`, `predicted`, `fertile`, `has_log`, `events`, `doses` exactly matching Spec 9.2 table.
- **Timezone default**: When `month` query parameter is omitted, default to current month evaluated in her stored timezone (`ZoneInfo(tz)`).
- **Graceful flow representation**: `has_log=True` with `flow="none"` indicates a check-in occurred without bleeding; `has_log=False` with `flow=None` indicates an unlogged day.
