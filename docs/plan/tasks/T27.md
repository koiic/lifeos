## Decisions

- **Synchronous vs Asynchronous Rebuild**: While background rebuild is enqueued via outbox for asynchronous execution, `GET /health/cycle` runs rebuild synchronously if any pending log/profile changes exist or if no active prediction exists yet, guaranteeing that client queries never see stale data and meet the < 2 s target.
- **Payload Encryption & AAD**: `health_profile`, `cycles`, and `cycle_predictions` encrypt all clinical data in `payload_enc` using the user's DEK with table-specific AAD (`health_profile:payload_enc:<user_id>:<user_id>`, `cycles:payload_enc:<cycle_id>:<user_id>`, `cycle_predictions:payload_enc:<prediction_id>:<user_id>`).
- **Prompt Representation**: `pending_prompt` on `GET /health/cycle` identifies unconfirmed intra-cycle bleeds (`{"kind": "new_period", "date": "<start_date>"}`) so the client can present "Is this a new period?" prompt to the user.
