## Plan

- Files to create or change:
  - `server/app/health/engine.py`: Pure-function bleed episode algorithm:
    - `is_flow_day`, `BleedEpisode`, `find_bleed_episodes`, `classify_episodes`, `check_auto_close`, `needs_length_confirmation`.
  - `server/app/health/schemas.py`: Add `PeriodStartIn`, `PeriodEndIn`, `PeriodActionResponse`.
  - `server/app/health/service.py`: Add `PeriodService` (or methods on `HealthService` / `DailyLogService`):
    - `start_period(user_id, date)`: sets flow Medium if empty, creates log if needed, emits `flow_changed`.
    - `end_period(user_id, date)`: sets last flow day, clears subsequent flow in episode if any, emits `flow_changed`.
  - `server/app/health/api.py`: Expose `POST /api/v1/health/period/start` and `POST /api/v1/health/period/end`.
  - `server/app/main.py`: Initialize `app.state.period` (or wire into health service).
  - `server/tests/health/test_bleed_episodes.py`: Pure-function tests for bleed-episode logic, TV6, TV9, TV10, auto-close, >10-day prompt, spotting exclusion.
  - `server/tests/health/test_period_api.py`: Integration tests for `/api/v1/health/period/start` and `/end`, flow update, outbox events, future date rejection, session auth.
- Approach:
  - Keep `engine.py` completely pure: no DB, no network, deterministic.
  - Layering: `api -> service -> repo` and `service -> engine`.
  - Bleed episode gaps: `<= 2` dry days between consecutive flow days belong to the same episode; `> 2` dry days start a new episode.
  - Intra-cycle bleeds: episodes starting `< 15` days after previous period start (and not in `forced_period_starts`) do not start a new period.
  - Spotting is never a flow day (PER-5, TV6).
- Migrations: None.
- New dependencies: None.

## Out of scope

## Decisions

- **Pure logic in `engine.py`**: Bleed episode grouping, period start classification, auto-close logic, and prompt checks are isolated in a pure module for complete testability and reusability by T26.
- **Period start idempotent flow update**: If a daily log already has `light`, `medium`, or `heavy` flow, `POST /health/period/start` preserves that intensity rather than downgrading or overwriting it.
- **Period end clears trailing bleed**: If trailing flow was logged after the confirmed end date within that episode, it is cleared to `none` to maintain consistency.
