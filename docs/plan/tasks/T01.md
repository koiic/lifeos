## Decisions

Internal choices the spec leaves open (not change requests):

- **Process slip:** this task file was first written after the tests instead of before them
  (loop step 3 before step 4). Content is unaffected; noted for honesty.
- **Module files scaffolded empty.** Spec 11.1 lists `api/service/repo/schemas/models/jobs.py` per
  module; they exist as docstring-only modules so import-linter contracts bind to real modules from
  day one. Platform files (config, db, crypto, …) are left to the tasks that own them.
- **import-linter contracts:** per-module layers `api | jobs` → `service` → `repo`; each module's
  `repo` importable only by its own `service`; `cryptography` only from `app.platform.crypto`;
  `sqlalchemy` forbidden in `api`, `service` and `jobs` (plan 4.2 "only `repo.py` files import
  SQLAlchemy sessions"; external packages are checked by top-level name, so this is stricter than
  "sessions"; T02/T03 may route transactions through a platform helper or refine the rule).
- **mypy:** `--strict` on all of `app/` (plan 4.2; a superset of spec 14.5's "strict on platform,
  health"), plus `ignore-without-code` so bare `# type: ignore` fails.
- **Per-module coverage** via `scripts/check_coverage.py`: exact comparison (no rounding before the
  gate); areas with no statements yet pass.
- **Makefile:** added `db` (prerequisite of `test-server` and `migrations`) and the coverage step.
  `secrets` now runs `gitleaks git` (history; the current name for the deprecated `detect`) and
  `gitleaks dir .` (working tree), so `make verify` also checks the uncommitted change. No check
  removed.
- **`.gitleaks.toml`:** default rules; skips third-party code, caches and the gitignored local
  secret files (`.env*`, `secrets/`, keys), which hold real secrets by design and never enter git.
- **`.gitignore`** also guards against real health data: `*[Ff]lo*[Ee]xport*`, `/data/`,
  `/private/`, and database dumps. The anonymised fixture path stays committable.
- **Local test database:** `infra/docker-compose.dev.yml`, PostgreSQL 16 on `127.0.0.1:54320`
  with local-only credentials; `scripts/ensure_db.sh` skips it when `DATABASE_URL` is set (CI).
- **Alembic** reads `DATABASE_URL` (spec 14.3 name). Which role runs migrations is part of CR-003.
- **OpenAPI files:** `server/openapi.json` (sorted keys) and `web/src/lib/api/schema.d.ts`
  (spec 11.1 `lib/api/` generated types); both prettier/ESLint-ignored as generated.
- **commitlint** lives in `web/` (one Node lockfile, plan 4.1). Subjects must name `Txx`, `CR-xxx`,
  `gate Mx` or `sync spec|plan vN`, which covers the formats the kit and plan use. `subject-case` is
  off because "T26 cycle engine" reads as sentence case.
- **Repository tooling tests live in `server/tests/tooling/`** (pytest), including the commitlint
  and stylelint tests, which run the pinned CLIs from `web/node_modules`. This keeps
  `@types/node` (not on the CR-002 list) out of the web project; Node types also no longer apply
  to `src/`. The first task needing Node types in web (likely T10's Vite config) raises a CR.
- **Version pins:** TypeScript 5.9 and ESLint 9, because typescript-eslint, openapi-typescript and
  eslint-plugin-jsx-a11y do not support TypeScript 6/7 or ESLint 10 yet. SQLAlchemy 2.0.54 (the
  spec names 2.0); Pydantic 2.13.5 declared explicitly (plan 4.2).
- **stylelint (plan 5.2)** enforces token-only values for colour, fill, stroke, font-family, every
  `*radius`, margin*, padding*, gaps, box-shadow, and transition/animation duration, delay and
  timing; functions are not exempt except `calc()` built only from tokens and numbers; `var()`
  fallbacks are banned; the `transition`, `animation` and `font` shorthands are banned in favour of
  longhands; `color()` and `color-mix()` are banned outside tokens.css. `font-size`, `line-height`,
  `font-weight` are not in plan 5.2's list; revisit in T11 once CR-005 adds the typography tokens.
  CSS Modules class names are camelCase (own convention, so they read as `styles.cardTitle`).
- **Known audit finding:** `npm audit` reports 8 high findings, all from one advisory
  (GHSA-vfj7-8cjw-p6xm, `braces` ≤ 3.0.3) inside stylelint's dependency tree. No fixed `braces`
  release exists. It is dev-only and does not affect `make verify`, but `make verify-full`
  (`npm audit --audit-level=high`) will fail at the M1 gate until upstream fixes it. Flag for T16
  and the gate.
