## Decisions

- **Client-error rate limit:** spec 11.7 says "rate-limited to 20 per minute" without a key. Before
  sign-in there is no session, and client IPs need the HMAC and `CF-Connecting-IP` trust work (T07).
  Read literally: 20 reports per minute for the endpoint, per API process (fixed window; with 2
  uvicorn workers the ceiling is 40), 429 problem with `Retry-After`. It runs before the body is
  read, so invalid and oversized reports count. Known weakness: anyone can use up the slots and
  silence genuine reports. **Follow-up for T07:** key it on the HMACed client IP (and the session
  when there is one).
- **Client-error payload:** `message` ≤ 500 chars, cleaned on the client and again on the server
  (everything between the outermost pair of each quote character, emails, UUIDs, dates and numbers
  become `<str>`, `<email>`, `<uuid>`, `<date>`, `<n>`), because browser messages can quote data
  (JSON.parse snippets, validation issues) and spec 11.7 says "no user data"; residual risk: free
  words in a message are kept. `route` must be a route pattern (`/`, `/today`, `/health/:tab`,
  `/settings/*`: lower-case words, `:params`, `*`, no digits, ≤ 200), so raw paths with ids or dates
  are rejected. `version` is semver (≤ 50). One `client.error` line through the scrubber. No auth
  (errors can happen before sign-in); the CSRF rule still applies.
- **Body size:** `BodySizeLimitMiddleware` caps request bodies at 1 MiB by default and 4 KiB for
  client errors (413 problem, declared or chunked). Imports (20 MB, spec 13.2) add their path in
  T41.
- **CSRF middleware is pure ASGI** (T02 code changed): it reads headers only and never wraps the
  body, so body errors keep their status. Behaviour unchanged; all T02 CSRF tests still pass.
- **OpenAPI:** every mutation documents 403 (CSRF) and 413 (body size) as problem+json; the
  client-errors request body is declared through `openapi_extra` because the route validates it
  after the rate limit.
- **Route patterns** come from `handle.pattern` on each route (a test makes every route declare its
  full path), not from rebuilding the URL, so malformed `%` URLs cannot break reporting and raw
  segments are never sent.
- **Fetch wrapper:** hand-written in `lib/api` over the generated `paths` types (no openapi-fetch,
  which is not an allowed dependency).
- **Placeholder Today route:** one lazy route so code-splitting and the router are exercised; its
  title comes from copy. T17 replaces it.
- **ESLint boundaries:** cross-feature imports are blocked by one generated block per feature folder
  and nesting depth (feature names read from `src/features/` when ESLint loads), so parent imports
  inside a feature stay allowed; features may not import `src/app`. Copy: `react/jsx-no-literals`
  for text children, plus `no-restricted-syntax` for user-facing attributes (`aria-label`, `title`,
  `alt`, `placeholder`, …) and strings chosen in conditional/logical JSX expressions. Strings stored
  in variables outside JSX cannot be caught by lint; the design-system reviewer covers them.
  `Date`, `fetch` and `XMLHttpRequest` are restricted as globals and as `window.`/`globalThis.`/
  `self.` properties. Inline style allows only object literals of custom properties (or a ternary of
  them). Generated types are importable from `lib/api` (`paths`, `components`).
- **Size budget:** `size-limit` measures `dist/assets/index-*.js` (the entry chunk, which today holds
  all initial JS). Review the glob when Vite starts emitting shared chunks the entry preloads.
- **404s** show the "Something went wrong" boundary and are not reported. The spec has no not-found
  copy; inventing it would need a change request, so it waits for one.
- **Error fallback styling:** plain `<main>`/`<h1>`/`<button>` (no styles, below the 44 px target);
  T11 or the first screen task renders it with the spec 5.5 `ErrorState` and `Button`.
- **React Router 6** (pinned by spec 6.1/11) has two moderate advisories fixed only in v7:
  GHSA-wrjc-x8rr-h8h6 (open redirect via backslash paths in `<Link>`/`navigate`) and
  GHSA-337j-9hxr-rhxg (SSR hydration; no SSR here, not applicable). They do not fail
  `npm audit --audit-level=high`. Rule for later tasks: never pass a `?next=`/redirect value to
  `navigate` without checking it is a same-app path (starts with one `/`, no `\`, no `//`). Moving to
  v7 would need a change request.
