## Decisions

- **Installability (CR-026, Ibrahim 2026-10-08):** Chrome's installability verdict plus its
  parsed manifest and a controlling service worker, in Playwright; the current `@lhci/cli` for the
  `lighthouse` script (`/install`, mobile; accessibility ≥ 0.95 and best practices ≥ 0.9 as
  errors, performance ≥ 0.85 as a warning until T49), run with Playwright's Chromium.
- **Icons:** `scripts/build_icons.py` draws the cycle-ring mark (`--accent` ring, `--sun` dot on
  Sorbet `--bg`) inside the maskable safe zone, so one drawing serves all four files; pure Python,
  deterministic, checked in `make verify` (`--check`). A placeholder until Zee picks the app's
  name and mark (spec 18).
- **Manifest:** `web/pwa.manifest.ts`, exactly 11.2; its colours are read from the tokens at build
  time (the same hex values the spec quotes). vite-plugin-pwa adds `"lang": "en"` by default; it
  is removed so the served file is exactly 11.2 (a `lang` would need a change request).
- **Service worker:** precache of the build (`**/*.{js,css,html,woff2,png,webmanifest}`: the
  shell, route chunks, the three Latin fonts, icons); navigations go to the network with a 3 s
  timeout (a plain `fetch` with an abort) and fall back to the precached `index.html`. No runtime
  copy of any page is kept (security review: Workbox's NetworkFirst cached each page by its full
  URL, so `/register?token=…` and `/recover?token=…` would have left live tokens in Cache Storage
  after sign-out; a journey now checks only the precache exists and holds no token). `/api/*` is
  excluded from the navigation route and has no runtime route, so it is never cached.
  `SKIP_WAITING` is accepted only from the app's own windows. The navigation handler is a pure
  function (`lib/sw/navigation.ts`, unit-tested with fake timers): the network's answer is used
  whatever its status (the server's redirects and error pages reach the browser); only a failure
  or the 3 s timeout gives the shell. For T15: serve `/sw.js` with `Cache-Control: no-cache` so
  updates are found.
  Typed with the `webworker` lib (`skipLibCheck` covers the DOM overlap).
- **Update toast:** `UpdatePrompt` in the app root (outside the router, so it shows on every
  screen, signed in or not), a floating `Toast` ("New version ready — Refresh"). It has no
  `z-index` (no new layer constant): rendered after the page it sits above it, and under sheets,
  dialogs and the lock screen. It sits `--space-4` above the safe area; when
  T17 adds the bottom bar it must sit above the bar (and pages get matching bottom padding) so it
  never hides the nav or a focused control (WCAG 2.4.11) — recorded for T17.
- **Install guide:** `/install` is a public route (no data on it), so it works right after
  registration and before signing in on the installed app. Registration (J1) goes there after the
  recovery codes unless installed or dismissed. Platforms: iOS (iPhone; iPadOS reports a Mac agent
  but has touch), Android (Chrome), anything else gets the desktop browser steps. "Not now" is
  remembered per browser (`lifeos.installDismissed`, a flag only). Chrome, Firefox and other
  browsers on iOS get a first step to open the page in Safari (only Safari adds to the Home
  Screen); the desktop steps are browser-neutral. The iOS Share step does not say where the
  button is (Safari's layout differs between versions and iPad), and says to try ••• first; the
  wording is part of the real-device check (15.2). Illustrations are the step's button drawn as an
  icon on a `--surface-tint` tile (decorative; ink on surface-tint), numbered on a `--sun` badge
  (highlights; accent-ink on sun); the list keeps `role="list"` because Safari drops list
  semantics when markers are hidden. Arriving on `/install` focuses its heading (WCAG 2.4.3).
  Android's steps say "Home screen" (Android's own term) while iOS and the page title say "Home
  Screen" (Apple's); the desktop steps keep the shared title. The intro promises only what the
  app does now (no offline data or reminders until T23/T14). The note
  says to use the Home Screen icon from now on (10.6: the tab and the installed app keep separate
  storage).
- **`index.html`:** the apple-touch-icon link; the manifest link is injected by the plugin;
  `theme-color` is set by `applyTheme` before the first render (no colour written in HTML).
