## Plan

- Files to create or change (all in `server/app/platform/` unless stated):
  - `config.py`: `Settings` (Pydantic model) and `load_settings(environ, secrets_dir)`.
  - `logging.py`: structlog JSON configuration, scrub processor, safe exception processor, uvicorn
    access log disabled (it logs client IPs).
  - `errors.py`: `Problem` and `FieldError` models; handlers for HTTP errors and validation errors.
  - `middleware.py`: request context (request id, timing, one access log line, catch-all 500),
    CSRF check (Origin + `X-LifeOS-Client` on POST/PUT/PATCH/DELETE), security headers.
  - `db.py`: async engine from settings, `ping()`.
  - `probes.py`: router with `GET /api/v1/healthz` and `GET /api/v1/readyz`.
  - `server/app/main.py`: `create_app(settings)`; module-level `app` for uvicorn.
  - `server/openapi.json`, `web/src/lib/api/schema.d.ts`: regenerated.
  - `server/migrations/env.py`: take the URL from settings (T01 security finding 3).
- Approach: platform code only; no module (auth, health, …) code. Middleware as Starlette
  middleware; problem responses built in one place; every response is a Pydantic model (plan 4.2).
- Migrations: none.
- New dependencies: `structlog` 26.1.0 (spec 6.1), `uvicorn` 0.54.0 (spec 14.2 runs the API with it;
  needed here to test that its logging cannot bring back access logs), `httpx` 0.28.1 (dev,
  CR-002, FastAPI test client).

## Decisions

Internal choices the spec leaves open (not change requests):

- **Paths:** every route, including the probes, lives under `/api/v1` (spec 9; 14.1 monitors
  `/api/v1/healthz`). 14.2's "healthcheck `/readyz`" is read as that same route.
- **CSRF failure:** 403 problem+json. Missing `Origin` is a failure. Exact match with `APP_ORIGIN`.
- **Problem `type`:** `about:blank` (the RFC 9457 default) with `title` = the HTTP status phrase,
  until a task defines specific problem types. 422 field paths drop the `body`/`query`/`path`
  location prefix (`mood`, `items.0.name`); `code` is the Pydantic error type; the submitted input
  is never echoed.
- **Unhandled errors:** 500 problem with a generic detail; logged as exception type plus stack frames
  (file, line, function) only — no exception message and no local variables, because both can carry
  user data (database errors quote values).
- **Request id:** a new UUID per request, bound to every log line of the request and returned as
  `X-Request-ID`. Incoming ids are not trusted.
- **Route in logs:** the route template (`/api/v1/daily-logs/{date}`), never the raw path or query
  string, so dates and ids in paths are not logged.
- **Settings without pydantic-settings** (not an allowed dependency): `load_settings()` reads env
  values from the environment and secrets from files in `/run/secrets` (`database_url`; a blank
  file counts as missing). `ENV` is required, so a deployment that forgets it fails at start-up. In
  `ENV=local` only, a `DATABASE_URL` environment variable and local defaults are accepted, so tests
  and `make dev` work without secret files (`tests/conftest.py`, `check_openapi.sh` and
  `check_migrations.sh` default `ENV` to `local`). `APP_ORIGIN` must use https outside local.
  Secrets are `SecretStr` and unwrapped only where the engine is built.
- **Migrations connection (known gap):** `migrations/env.py` uses `database_url` (the `lifeos_app`
  connection in 14.3). Spec 7.3 says `lifeos_owner` runs migrations, but 14.3 has no owner
  connection; that is CR-003 item 5, decided before T03. Not pre-empted here.
- **Logs:** `method` is treated as part of "routes" in 12.5 (method + template), and only known
  methods are logged (others as `OTHER`). Exception type and frames are the "error reports" of 12.5.
  Standard-library loggers go through the same scrubber; library loggers are kept at WARNING and
  above because their INFO messages are free text (URLs, SQL). Free-text messages are never
  scrubbed, so app code passes data as fields, never inside the message.
- **Scrubber:** suffix match is case-insensitive (camelCase payloads such as `displayName`); any
  mapping or set is walked; values that are not plain data (strings, numbers, booleans, `None`,
  UUIDs, dates, enums) are rendered as `<TypeName>`. The public `scrub` uses structlog's
  `EventDict` processor type (plan 4.2 "no `Any` in public functions": the `Any` is inside
  structlog's own alias, which the processor protocol requires).
- **CSRF is deny-by-default:** every method except exactly `GET`, `HEAD` and `OPTIONS` is checked.
- **Validation messages:** custom validator errors (`value_error`, `assertion_error`) get a fixed
  message, because their text could quote the input.
- **OpenAPI:** errors are documented as `application/problem+json` with `Problem`; FastAPI's default
  `HTTPValidationError` is replaced for every 422 (`install_problem_openapi`).
- **T15 hand-off:** run uvicorn with `--no-access-log` as well (belt and braces with the logger
  being disabled here).
- **API docs:** `/docs` and `/redoc` disabled everywhere (Swagger UI loads assets from a CDN);
  `/api/v1/openapi.json` served only in `local`. The committed `openapi.json` is generated from
  `app.openapi()` and is unaffected.
- **Security headers (12.4)** included here because 12.4 assigns them to FastAPI middleware and no
  other task builds that middleware.
