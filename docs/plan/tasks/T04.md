## Decisions

- **Wrapped DEK format:** the same `0x01 ‖ nonce ‖ ciphertext ‖ tag` as field encryption, AAD
  `dek:<user_id>`; the KEK version is stored in `users.kek_version`, not in the blob.
- **One error type:** every failure (wrong length, unknown version byte, tag mismatch, unknown KEK
  version, unwrapped key of the wrong length, invalid JSON or schema after decryption) raises
  `DecryptionError("decryption failed")`, raised outside any `except` block so it has no cause and
  no context (a validation error would quote the plaintext).
- **Keys never print:** `DataKey`/`MasterKey` hide their bytes in `repr`/`str` and refuse pickling;
  there is no fingerprint or other key-derived value (nothing asked for one; it would invite
  logging). Field encryption accepts only a `DataKey`; the KEK only wraps DEKs.
- **Validated inputs:** AAD names must be lower-case identifiers and ids `uuid.UUID`, so the AAD
  string is unambiguous; KEK versions are integers ≥ 1 (`users.kek_version` default 1).
- **Payload evolution:** unknown fields are kept (`extra="allow"`): after a rollback, older code can
  read rows written by newer code and rewrite them without losing the newer fields. Rejecting them
  (row unreadable) or ignoring them (field dropped on rewrite) were the alternatives.
- **DEK cache:** at most 5 minutes from `put` (reads do not extend it), expired entries swept on
  every call; account deletion and session revocation must `evict` (T06, T08, T43).
- **Notes for later tasks:** loggers and error reporters must never capture frame locals (decrypt
  frames hold plaintext and key bytes; T02's logger already records frames without locals); key
  bytes are immutable `bytes` that cannot be zeroed, accepted under spec 12.1's server-compromise
  residual risk — containers should disable core dumps and the host avoid unencrypted swap (T15).
- **HKDF** is listed in spec 6.1 but no part of 12.2 derives keys, so it is not used.
- **CR-011** raised: how several KEK versions are configured during rotation (blocks T06).
