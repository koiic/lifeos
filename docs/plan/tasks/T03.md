## Decisions

- **Roles outside the migration:** roles are cluster-wide, so `server/migrations/roles.sql` creates
  them (NOLOGIN, idempotent) as the database superuser; the migration only grants and creates
  policies. T15 makes `lifeos_owner`, `lifeos_app`, `lifeos_admin_ro`, `lifeos_jobs` and
  `lifeos_dispatcher` login roles with passwords from secrets.
- **Owner bypasses RLS:** `FORCE ROW LEVEL SECURITY` applies to table owners, so the `SECURITY
  DEFINER` lookup functions only work if `lifeos_owner` bypasses RLS. Locally the owner is the
  superuser; T15 must create `lifeos_owner` with `BYPASSRLS`. Ibrahim: please include this in the
  CR-003 spec sync.
- **Unset `app.user_id`:** policies use `NULLIF(current_setting('app.user_id', true), '')::uuid`, so
  an unset or reset (empty) setting matches no rows instead of raising a cast error.
- **Tests use `SET ROLE`** from the superuser connection; RLS and grants apply to the current role.
- **Migrations run as `lifeos_owner`:** `env.py` runs `SET ROLE lifeos_owner` (then commits it) on
  every connection, so every object, `alembic_version` included, is owned by the non-superuser
  owner even when connected as a superuser locally or in CI. `roles.sql` gives the owner CREATE on
  the database (trusted `citext`) and on schema `public`, revokes CREATE on `public` from PUBLIC
  and grants USAGE to each role explicitly.
- **Narrower grants than 7.3's wording** (least privilege; recorded in the CR-003 addendum for the
  spec sync): `lifeos_admin_ro` reads `sessions` and `invites` without `token_hash`;
  `lifeos_dispatcher` reads only the `user_settings` columns sending needs (no PIN hash, no
  consent), and updates `reminders(status, attempts, sent_at, fire_at)` only.
- **Lookups are schema-qualified** (`public.users`, `p_email::public.citext`) on top of the fixed
  `search_path`. T06 must give unknown and known emails the same response and similar timing on
  password and recovery sign-in (the email lookup reveals existence).
- **Audit tables:** `lifeos_app` can UPDATE/DELETE `audit_log` and `auth_events` because 7.3 says
  "CRUD on all tables"; CR-010 proposes append-only (T07 blocked until decided).
- **Notes for later tasks:** foreign keys are checked without RLS, so services must load a parent
  row under RLS before writing a child that references it (T26+, T30, T35…); only the `migrate`
  container may receive `database_owner_url` (T15); the app should connect as `lifeos_app` locally
  too so development and e2e run under RLS (T05/T06/T15).
- **Flag for T45:** `lifeos_backup` with `pg_read_all_data` alone cannot `pg_dump` tables with forced
  RLS; physical backups (pgBackRest, 14.2) are unaffected. T45 decides (likely a CR for BYPASSRLS).
